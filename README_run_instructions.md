# NIMA Phase II — Blender Walkthrough Blockout

Pipeline:

```
NIMA_Phase2_Master_Schedule_LOCKED-3.xlsx
            │
            ▼
   extract_schedule_to_json.py        (outside Blender)
            │
            ▼
        nima_schedule.json
        nima_schedule_extractor_report.txt
            │
            ▼
   build_nima_blender.py              (inside Blender 4.x)
            │
            ▼
   Blender scene + nima_blender_build_report.txt
            │
            ▼
   Manual visual review in Blender (no FBX export from this pipeline)
```

The locked Excel workbook is the absolute source of truth. SVGs are reference
only and are not parsed. No exterior, site, parking, landscaping, or final
exterior / roof construction is generated. No FBX export is performed.

## 2. Required Python packages

The extractor runs in plain Python 3.9+ (outside Blender) and needs:

- `openpyxl` (≥ 3.1)

Install:

```bash
python3 -m pip install --user openpyxl
```

The Blender script runs inside Blender 4.x. Blender already ships its own
Python — no `pip install` is needed inside Blender. The script uses only
`bpy`, `bmesh`, `mathutils`, `math`, `os`, `json`, `sys`, all of which are
built-in to Blender.

## 3. Running the extractor

From the repo root:

```bash
python3 extract_schedule_to_json.py
```

Optional arguments:

```bash
python3 extract_schedule_to_json.py \
    --xlsx /path/to/NIMA_Phase2_Master_Schedule_LOCKED-3.xlsx \
    --out  /path/to/output_dir
```

If `--xlsx` is omitted the extractor automatically uses the highest-suffixed
`NIMA_Phase2_Master_Schedule_LOCKED*.xlsx` it finds next to the script.

### Extractor outputs

- `nima_schedule.json` — canonical, scrubbed JSON schedule consumed by the
  Blender script. Polygon vertices for the four Notes-driven polygon rows
  (`ZONE_GRND_RECYC`, `ZONE_F2_OVERLOOK_POLYGON_VERIFIED`, `ZONE_PALLET`,
  `ROOF_POLYGON_VERIFY`) are pre-extracted in both grid and meter form.
- `nima_schedule_extractor_report.txt` — counts, polygon-priority decisions
  for each polygon row, segment-list parse counts, non-numeric values found
  in numeric columns, list of skipped rows, and a forbidden-elements check.

## 4. Running the Blender script

### Option A — headless / batch

```bash
blender --background --python build_nima_blender.py
```

The script writes `nima_blender_build_report.txt` next to
`nima_schedule.json` and prints the same report to stdout. The Blender
scene is built in the in-memory `.blend` and is **not** saved to disk by
default — open Blender interactively after review to save / export.

### Option B — interactive

1. Open Blender 4.x.
2. Open `build_nima_blender.py` in the Text Editor.
3. Click **Run Script** (or press `Alt+P`).
4. Review the scene. Save the `.blend` manually if needed (`File → Save As`).

### Where the script looks for `nima_schedule.json`

In order:

1. `$NIMA_SCHEDULE_JSON` environment variable
2. The directory of `build_nima_blender.py`
3. The directory of the currently open `.blend`
4. The current working directory

## 5. What the Blender build produces

### Root collections (always created)

- `NIMA_F1` — first-floor zones, doors, slabs, glass curtain wall, equipment proxies.
- `NIMA_F2` — second-floor zones, F2 overlook polygon, F2 glass perimeter wall.
- `NIMA_HighBay` — high-bay volume + concrete slab and industrial wall reference.
- `NIMA_Roof` — interior height / closure references only. No exterior roof construction.
- `NIMA_Spawn` — spawn marker (red disk) and a south-facing arrow (DEBUG_MODE only).
- `NIMA_Debug_Reference` — VERIFY-status objects and Debug-Only overlays.
- `NIMA_Rules_Materials` — material catalog, rule rows, spot-check references.

### Geometry rules in effect

- **Walls, glass, doors, panels, plates, gates, edges and rails are built as
  3D solids with thickness** (default thicknesses applied when the row's
  `Thickness M` is missing). No zero-thickness planes for visible barriers.
- **Polygon zones** are extruded from `Base Z M` to `Top Z M` using the four
  user-decision corners (or 16 vertices for `ROOF_POLYGON_VERIFY`).
- **F2 overlook glass perimeter wall (`ELEM_F2_GLASS_PERIMETER_WALL`)** is
  built per-edge against the F2 overlook polygon (`ZONE_F2_OVERLOOK_POLYGON_VERIFIED`).
  The edge **SW → NW** is intentionally skipped to honor
  `RULE_F2_STAIR_TO_OVERLOOK_OPEN` (no wall, glass, guard or barrier between
  the stair cutout and the SW corner of the F2 overlook / lobby route). Edit
  the `F2_OVERLOOK_OPEN_EDGES` constant at the top of `build_nima_blender.py`
  if a different open edge is verified later.
- **Doors**: magenta = closed / non-working / blocked-route marker; yellow =
  working / passable; dark gray = overhead industrial. Adjacent paired door
  markers are kept as separate solids — pair them visually as needed.
- **GRND/RECYC + Pallet stack**: GRND/RECYC at Z 0 → 3.09; the 0.0762 m
  steel plate at Z 3.0138 → 3.09 (top flush with F2 slab); Pallet Storage at
  Z 3.09 → 5.99. All three share the same rotated rectangle footprint.
- **Generated stairs are NOT created.** Only the stair opening / import zone
  (`ZONE_STAIRS`) and a stair-void guardrail (`ELEM_RAIL_STAIR_VOID`,
  VERIFY) are produced.
- **Reception furniture / casework / millwork are NOT created.**
- **Exterior, site, parking, landscaping, sidewalks, roads, terrain, and
  detailed exterior facade / roof construction are NOT created.**
- **No forbidden building elements** are created in any object name,
  collection name, mesh name, label, or log line. The extractor scrubs free
  text fields before they are forwarded to the builder.
- **No FBX export.**

## 6. Configuration knobs at the top of `build_nima_blender.py`

```python
DEBUG_MODE = True   # shows Debug-Only height posts, debug overlays, spawn arrow
F2_OVERLOOK_OPEN_EDGES = [("SW", "NW")]  # honors RULE_F2_STAIR_TO_OVERLOOK_OPEN
```

For the first validation build leave `DEBUG_MODE = True`. For a clean
walkthrough or screenshots, set it to `False` and re-run — the Debug-Only
height posts, the spawn arrow, and the high-bay rotation overlays will be
omitted.

## 8. Troubleshooting

### `ModuleNotFoundError: No module named 'openpyxl'`
Install with `python3 -m pip install --user openpyxl`. Use the Python that
will run the extractor (Blender's bundled Python is not used for this step).

### `nima_schedule.json not found`
Set the env var before running Blender:
```bash
export NIMA_SCHEDULE_JSON=/full/path/to/nima_schedule.json
blender --background --python build_nima_blender.py
```

### Polygon zone looks wrong (open / inside-out / inverted faces)
The extractor preserves vertex order from Notes (NW → NE → SE → SW for
labeled corners; in-text order for unlabeled). If a polygon comes out
inside-out, recalc normals on the object in Blender (`Edit Mode → Mesh →
Normals → Recalculate Outside`), or reorder the corner labels in the Notes
cell of the source workbook.

### A row I expected didn't render
Check `nima_blender_build_report.txt`:
- Skipped rows are listed with the reason.
- "Labels-only rows" are listed when dimensions were unsafe.
- "Polygons skipped" lists polygon rows whose vertices could not be parsed.
Then re-check that row's `Generate Geometry?`, `Geometry Type`,
`Coordinate / Placement Type`, and `Notes` in the workbook.

### Material color is orange/translucent for a row I didn't expect
Orange/translucent = `MAT_Debug_VERIFY`. Either the row is `VERIFY` status
or its `Material Placeholder` is unknown. Look in
`nima_blender_build_report.txt` under "Unknown material placeholders".

### Performance / lightweight target
The build is intentionally low-poly (boxes and prism extrusions). If the
scene feels heavy, set `DEBUG_MODE = False` to drop debug overlays and the
seven height posts.

## 9. Known limitations and remaining VERIFY items

The locked workbook flags 36 geometry rows as `VERIFY`. They are rendered
translucent in `NIMA_Debug_Reference`. The most important ones the user
should personally re-check in Blender:

| Element ID | What to verify |
|---|---|
| `ZONE_HIGHBAY` | Rotation: 0° vs 10°. Overlay both in Phase 0/1. |
| `ZONE_HIGHBAY_VOID` | The 7.22 m open volume between F2 slab and high-bay top. |
| `ZONE_HIGHBAY_OVERLOOK` | F2 edge along the high-bay; railing path. |
| `ZONE_MEZZ` | Mezzanine bbox vs final extents. |
| `ELEM_RAIL_STAIR_VOID` | Stair-void guardrail location and height. |
| `ELEM_OVERHEAD_VERIFY` | Overhead-door panel placeholder. |
| `ROOF_POLYGON_VERIFY` | Top Z 11.91 m only — Base Z and Height are "varies"; built as outline. |
| `ROOF_HIGHBAY_TOP_REF` / `ROOF_LOBBY_CONN_TOP_REF` | Height-post references. |
| `ROOF_STRUCT_ABOVE_HB` | 1.61 m structure-zone above the high-bay only. |
| `ROOF_OVERHANG_VERIFY` | Skipped (Generate=No) — re-check before any future build. |
| `ROOF_PARAPET_EDGE` | Reference perimeter only. |
| `F1_GLASS_CW_SEGMENTS`, `F1_WINDOWS_HB_EAST_NORTH`, `F2_GLASS_CW_SEGMENTS` | Segment placement and rotation; sill/header heights default to 0.9–2.4 m and may need adjustment. |

Other intentional limitations:

- **Door rotation is not modeled.** All door panels are axis-aligned solids.
  If a door must follow the high-bay's verified angle, rotate it manually
  after the build (it is 1:1 and named, so it can be selected easily).
- **High-bay rotation is not applied.** The high-bay bbox is axis-aligned;
  rotation remains VERIFY per the workbook.
- **Mezzanine loading-gate orientation** is axis-aligned; verify against
  the actual mezzanine edge.
- **Reception, casework, millwork, and exterior** are deliberately excluded
  per the build scope.
- **No FBX export.** Manual export will be handled after visual review.
- **SVGs are not parsed.** They are reference aids only.
